1. Purpose

Dokumen ini mendefinisikan:

- arsitektur consensus inti STG,
- validator coordination,
- block finalization,
- synchronization logic,
- fork mitigation,
- dan sovereign consensus continuity.

---

2. Consensus Objectives

Consensus dirancang untuk:

- menjaga chain liveness,
- memastikan deterministic finality,
- memitigasi malicious validator behavior,
- menjaga synchronization stability,
- mendukung scalable governance,
- dan menjaga long-term decentralized resilience.

---

3. Consensus Principles

Consensus wajib:

- deterministic,
- auditable,
- fault tolerant,
- replay-safe,
- synchronization-safe,
- dan governance-compatible.

---

4. Consensus Architecture

Consensus STG menggunakan model:

- validator-based coordination,
- epoch-driven rotation,
- stake-aware participation,
- event-based synchronization,
- dan modular cryptographic validation.

---

5. Core Consensus Components

Consensus layer terdiri dari:

- validator coordination engine,
- block proposal mechanism,
- finalization logic,
- slashing enforcement,
- validator rotation policy,
- synchronization layer,
- dan governance compatibility framework.

6. Validator Roles

Validator bertugas untuk:

- memverifikasi transaksi,
- mengusulkan blok,
- memvalidasi state transition,
- menjaga synchronization,
- dan mempertahankan network integrity.

7. Consensus Participation Rules

Validator wajib:

- memenuhi staking requirement,
- menjaga uptime,
- mematuhi signing policy,
- mematuhi rotation policy,
- dan menjaga infrastructure integrity.

11. Finalization Rules

- quorum validator tercapai,
- signature threshold terpenuhi,
- synchronization state valid,
- dan fork boundary tidak dilanggar.

12. Quorum Policy

Consensus wajib mendefinisikan:

- minimum validator participation,
- fault tolerance threshold,
- slashing boundary,

13. Fault Tolerance Model

Consensus wajib tahan terhadap:

- validator downtime,
- malicious signing,
- network partition,
- delayed propagation,
- dan synchronization instability.

---

14. Fork Mitigation

Consensus wajib memitigasi:

- accidental fork,
- malicious fork,
- replay fork,
- governance fork,
- dan synchronization divergence.

---

15. Slashing Integration

Validator dapat dikenai slashing apabila:

- double-signing,
- malicious state injection,
- prolonged downtime,
- replay violation,
- atau consensus manipulation terdeteksi.

---

16. Synchronization Layer

Synchronization layer wajib:

- deterministic,
- checkpoint-aware,
- latency-tolerant,
- recovery-compatible,
- dan validator-safe.

---

17. Checkpoint Architecture

Checkpoint digunakan untuk:

- rapid synchronization,
- validator recovery,
- fork resolution,
- disaster recovery,
- dan historical verification.

---

18. Validator Admission

Validator baru wajib:

- governance-approved,
- infrastructure-validated,
- cryptographically compatible,
- dan synchronization-tested.

---

19. Consensus Replay Protection

Consensus layer wajib melindungi terhadap:

- duplicate proposal,
- replay voting,
- stale validator identity,
- cross-epoch replay,
- dan malicious synchronization injection.

---

20. AI Monitoring Boundaries

STG-AI diperbolehkan:

- membaca consensus telemetry,
- mendeteksi anomaly,
- menghasilkan synchronization analysis,
- memberi validator diagnostics.

STG-AI TIDAK diperbolehkan:

- melakukan consensus override,
- mengubah validator state,
- mengusulkan blok,
- atau memegang validator signing authority.

---

21. Emergency Consensus Protection

Consensus wajib memiliki:

- emergency isolation policy,
- validator quarantine mechanism,
- fork containment policy,
- dan recovery coordination framework.

---

22. Governance Interaction

Governance dapat:

- memperbarui consensus parameter,
- menyetujui validator policy,
- mengaktifkan emergency protection,
- dan mengaudit consensus integrity.

Governance TIDAK boleh:

- memalsukan finalized block,
- menghapus historical consensus state,
- atau mem-bypass validator quorum.
